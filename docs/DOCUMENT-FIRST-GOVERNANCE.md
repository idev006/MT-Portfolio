# MT-Portfolio — DOCUMENT-FIRST PROJECT GOVERNANCE

**Status:** Governing policy, owner-directed (2026-10-17).

## Core rule
**Documents direct everything.** The approved documentation, rather than prompts, code, renderers or AI improvisation, establishes project scope, facts, release rules and the workflow. AI interprets and creates within those bounds. It may propose changes but cannot silently change approved content.

## Source authority order
1. Latest explicit owner instruction, recorded as a decision with timestamp.
2. This governance document for process and authority.
3. `docs/infographic-as-code/content-lock.json` for exact approved factual scope and text.
4. `docs/infographic-as-code/design-contract.json` for active visual constraints and export specification.
5. `docs/infographic-as-code/evidence-register.md` for status, authorization and source provenance.
6. `docs/infographic-as-code/qa-checklist.md` and Production Lessons for release validation and learned pitfalls.
7. README/SSOT/narrative drafts and legacy guides only when consistent with above.

When files conflict, stop the affected aspect, document the conflicting passages and apply higher-priority authority. Never fill uncertainties by inventing claims.

## Operating sequence
1. **Read:** At start of every new chat/read handoff, then this governance policy, locked content, design contract, evidence register, creative workflow, QA and lessons before production.
2. **Audit:** Map every page claim to a content ID and evidence state; make a ledger of any unclear/contradictory policy.
3. **Direct:** Form distinct AI-led Art Direction concepts for each page. Do not use Design-as-Code, Python card layout, automatic section geometry or an old draft as artwork.
4. **Create:** Build three independently art-directed A4 portrait images. Use genuine owner photos only with verified provenance; use conceptual art solely as non-evidence. Thai text is real typesetting and must match approved copy.
5. **Verify:** Evidence authenticity, exact text, print legibility, art direction, file metrics, privacy, asset hashes, human proofreading and owner visual approval.
6. **Release:** Until every mandatory gate passes, label as DRAFT / PRODUCTION CANDIDATE, not FINAL. Preserve output manifest and decision record.

## Document ownership & change control
- Owner approves scope, factual claims, visual acceptance and final release.
- AI may implement documentary maintenance but must log changes with rationale, changed files and status, and avoid overwriting owner-confirmed facts.
- Before changing approved copy, ask for specific new owner authorization. Do not re-ask facts already approved.
- Changes to project policy require a traceable commit/PR with explicit superseding guidance; legacy instructions must be marked obsolete rather than silently reused.
- For every new chat, handoff must state latest active policy, source revision, pending evidence, current artifact status and precise next action.

- Three separate A4 portrait infographic images at >=2480×3508 px.
- No actual/generated unit logos. Owner's latest instruction authorizes an OPTIONAL empty thin dashed logo placeholder for later manual insertion; this supersedes earlier 'no logo placeholder' policy. Page 1 has an empty portrait slot at height:width 4:3.
- Thai numerals in visible copy except the exact approved `ตำรวจภูธรภาค 6` heading.

- Owner-confirmed metrics remain marked owner confirmed / independent artifacts pending when appropriate.
- No invented people, achievements, timings, precision, awards, visual evidence, interfaces or activity photographs.

## Definition of done
**Document-compliant** is not the same as visually excellent. FINAL requires both factual/evidence release gates and meaningful, independent visual Art Direction review, with explicit owner approval. Code may assist only with validation and technical exports, never with creative layout.
