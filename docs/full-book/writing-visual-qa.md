# Writing, Visual & Release QA — Full Book
## Mandatory preflight
- [ ] ชื่อหัวข้อบังคับทุกหัวข้อและสาระย่อยครบ; ถ้าจัดกลุ่มใหม่ยังตรวจย้อนกลับหัวข้อเดิมได้
- [ ] สถานะข้อเท็จจริงทุกจุด: หลักฐานต้นฉบับ / เจ้าของยืนยัน / ต้นแบบ / แนวทางต่อยอด / รอตรวจ
- [ ] ไม่มีผลตัวเลขจากการสมมติ; ไม่แก้ไขเลขโดยตีความเอง
- [ ] ชื่อ ยศ ตำแหน่ง คุณวุฒิ เลขคำสั่ง ปี พ.ศ. ตรวจจากหลักฐานทางการ
- [ ] เขียนภาษาผู้บริหารก่อน ศัพท์เทคนิคอยู่ในวงเล็บ; สอดคล้องกับ Audience Blueprint
- [ ] งานสื่อองค์กรและ LINE Sticker มีตำแหน่งทั้งบทความสามารถและบทผลงานที่หลักฐานรองรับ ไม่ตกหล่น
- [ ] ไม่อ้างว่ามีระบบบริการประชาชน/ระบบตรวจบัญชี LINE ใช้งานจริง เว้นตรวจได้
- [ ] ไม่อ้างว่าโปรแกรมสหกรณ์วิเคราะห์ข้อมูล; ทำงานวางตรา/ลายเซ็น/ข้อความเป็นชุด
- [ ] งานวิทยุเป็นรายงานจากข้อมูลเดิม ไม่พัฒนาฐานข้อมูลและไม่กล่าวว่าเป็นผู้ดำเนินการจำหน่าย
- [ ] งานศึกษา MTSecurity/AI CCTV แสดงเป็นศึกษา/ต้นแบบ
- [ ] งานก่อนนโยบาย ผบ.ตร. ๒๕๗๐ ห้ามเขียนเป็นงานตามคำสั่งหลังประกาศ
- [ ] ตรวจชื่อและวันที่บุคคลสำคัญ/พิธีการจากเอกสารที่เป็นทางการก่อนเผยแพร่
- [ ] ภาพประกอบ ไม่สร้างเจ้าหน้าที่หรือเหตุการณ์เทียมให้ดูเป็นหลักฐาน
- [ ] Screenshot ต้องเป็นภาพจริงจาก Drive; ถ้าตกแต่ง/ตัดข้อมูลให้ระบุเป็นภาพประกอบ
- [ ] ตรวจ PDPA ข้อมูลประชาชน เบอร์โทร ID เลขบัตร สถานที่ที่เป็นข้อมูลอ่อนไหว ก่อนนำภาพเข้าหนังสือ
- [ ] ภาษาไทยสะกดถูกต้อง ลำดับชั้นหัวข้อถูกต้อง ภาพคม อ่านได้เมื่อพิมพ์ A4
- [ ] แยกโครงเล่มให้อ่านเร็ว/ละเอียด บทนำแต่ละบทมี key message ที่พิสูจน์ได้
- [ ] ส่งให้เจ้าของตรวจและอนุมัติภาพรวม ก่อนเรียก FINAL

## Stop issues identified from existing Word
- คำกล่าวเรื่องรายงานร้องเรียนจากหลายชั่วโมงเป็นไม่กี่นาที ยังต้องตรวจหลักฐาน
- ระดับความสำเร็จของกล้องจดจำใบหน้า/จับไม่สวมหมวกกันน็อก ต้องยืนยันว่าแค่ต้นแบบหรือทดลอง
- ข้อมูลส่วนบุคคลใน Word มีเลขบัตรประชาชนและวันเกิดเต็ม: ห้ามเผยแพร่ลง GitHub หรือบทสรุปสาธารณะ
- ข้อความจาก readme.txt เกี่ยวกับพิธีการและสถานะบุคคลต้องตรวจความถูกต้องก่อนใช้
