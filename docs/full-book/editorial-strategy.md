# Editorial Strategy — จัดลำดับเนื้อหาเพื่อผู้ประเมิน (PROPOSED)
วันที่ 17 ตุลาคม 2569 | โครงการ MT-Portfolio เล่มเต็ม

## หลักการ: วัตถุดิบ → เข้าใจผู้รับสาร → ปรุงอย่างมีหลักฐาน → จัดเสิร์ฟให้เข้าใจง่าย
อุปมา “ปรุงอาหารให้เหมาะกับลูกค้า” ใช้เพื่อออกแบบการสื่อสาร ไม่ใช่การเขียนเอาใจโดยบิดเบือนข้อเท็จจริง
- **วัตถุดิบ:** ประวัติ ตำแหน่ง ภารกิจ ผลงาน สถิติที่ยืนยันได้ ภาพจริง ใบประกาศ คำบรรยายจากเจ้าของ
- **ผู้รับสาร:** ผู้บริหารอ่านเร็ว; กรรมการตรวจรายละเอียด; เจ้าหน้าที่รวบรวม/ค้นหลักฐาน พิจารณาหน้าที่ตามเกณฑ์ ไม่เดารสนิยมบุคคล
- **เมนู/สารอาหาร:** คุณสมบัติที่ต้องประเมินและประโยชน์ราชการ หัวข้อบังคับ ๑–๑๓ ครบ
- **วิธีปรุง:** จัดลำดับความสำคัญ เรียบเรียงภาษาที่เข้าใจง่าย กรองข้อกล่าวอ้าง ตรวจสอบที่มา
- **การจัดเสิร์ฟ:** สรุปหน้าเดียว → รายงาน ๓ หน้า → เล่มละเอียด ภาพและกราฟิกช่วยสื่อสาร ไม่ประดิษฐ์หลักฐาน
- **ชิม/ตรวจคุณภาพ:** ความครบตามแบบ ความถูกต้อง ความอ่านง่าย ระดับการกล่าวอ้างเหมาะสม เจ้าของตรวจอนุมัติ

## ข้อบังคับเกี่ยวกับการจัดลำดับ
1. **ลำดับหัวข้อบังคับ:** หัวข้อหลักตามแบบต้องครบและค้นได้อย่างชัดเจน ห้ามสลับหรือลบโดยไม่มีข้อกำหนด/อนุมัติ
2. **ลำดับผลงานในหัวข้อ:** เรียงด้วยความเกี่ยวข้องกับตำแหน่งและเกณฑ์ประเมิน → ผลสัมฤทธิ์ต่อราชการ → ความน่าเชื่อถือหลักฐาน → บทบาท/ความยาก → ความน่าสนใจ
3. **ลำดับเนื้อหาในผลงาน:** ผลที่ตรวจสอบได้ (ถ้าชัดเจนใช้เป็นหัวข้อดึงสายตา) → ปัญหา/เหตุจำเป็น → บทบาทและสิ่งที่ทำ → ผลประโยชน์ → หลักฐาน → แนวทางต่อยอด (ระบุอนาคต)
4. **จังหวะหนังสือ:** เปิดด้วยภาพรวมที่แข็งแรง; ช่วงกลางใช้กรณีศึกษาหลัก/ภารกิจ; ปิดด้วยหลักฐานและบทสรุปที่สุขุม ไม่เรียงความสำคัญลดลงจนท้ายเล่มไร้คุณค่า
5. **หลักฐานอยู่เหนือความโดดเด่นด้านกราฟิก:** ไม่มี claim ใหม่จากชื่อไฟล์หรือภาพสังเคราะห์

## Editorial Priority Rubric (เพื่อช่วยคัดเลือก ไม่ใช่คะแนนราชการ)
ให้คะแนนแต่ละมิติ 0–4 โดยอาศัยหลักฐาน:
- R: สัมพันธ์กับหน้าที่/ตำแหน่งเป้าหมาย (น้ำหนัก 30%)
- I: ผลต่อราชการ/ผู้รับบริการ (30%)
- E: คุณภาพหลักฐาน (20%)
- O: บทบาทและความยากในการรับผิดชอบ (15%)
- C: ความชัดเจน/น่าจดจำในการสื่อสาร (5%)
สูตรเพื่อเรียงภายในบท: 0.30R + 0.30I + 0.20E + 0.15O + 0.05C
**ห้าม** ให้คะแนนเมื่อข้อมูลไม่พอ ให้สถานะ NEEDS_EVIDENCE; ไม่ใช้คะแนนนี้ตัดสินการแต่งตั้งหรือชดเชยเกณฑ์ทางการ

## การให้พื้นที่เนื้อหา
A: กรณีศึกษาหลัก (ปัญหา–บทบาท–ผล–หลักฐาน) ให้พื้นที่มาก
B: ผลงานเสริม แสดงความหลากหลายและประโยชน์ ใช้พื้นที่พอเหมาะ
C: ภารกิจ/กิจกรรมที่มีส่วนร่วมจริง ให้ภาพ+ข้อความสั้นเพื่อลดการซ้ำ
D: ต้นแบบ/แนวคิด ศึกษาและต่อยอด ต้องทำป้ายสถานะไม่ใช่งานใช้จริง
เลือก A/B/C/D จาก evidence และข้อกำหนดของแต่ละบท ไม่ใช่ชื่อเทคโนโลยีที่ดูน่าตื่นเต้น

## ตัวอย่างลำดับเบื้องต้นในหมวดผลงาน (ยังไม่ใช่การจัดอันดับที่รับรอง)
- การจัดทำรายงาน ๑๙๑ ประจำวัน (ตัวเลขประหยัดเวลาเจ้าของยืนยัน รอตรวจหลักฐาน)
- การเตรียมข้อมูลและภาพรวม Dashboard ๑๙๑ (แยกจากรายงานประจำวัน)
- ฉลามบก / IPB (ผลงานหน่วยเดิม ต้องตรวจช่วงเวลา/รายละเอียด)
- โปรแกรมจัดการ PDF และใบเสร็จ (ตรวจการนับซ้ำกับ MTPDFLogo)
- Excel/Macro งานช่วยหน่วยอื่น
- Infographic, Poster, One-page, Presentation, LINE Sticker
- LINE Bot (ยืนยันบทบาทและระดับการนำไปใช้)
ปรับลำดับใหม่ได้เมื่อหลักฐานและตำแหน่งเป้าหมายชัดขึ้น

## Quality Gates
- ทุกบทมี key message เดียวหลัก; ทุกผลงานสำคัญมี evidence ID
- ผลงานเดียวมีบทหลักหนึ่งแห่ง ส่วนบทอื่นใช้เลขอ้างอิง
- ไม่กล่าวอ้างยอดผู้ใช้ ผลประหยัดเวลา รางวัล หรือการใช้งานจริงจากภาพเพียงอย่างเดียว
- หัวข้อบังคับไม่ถูกแทนที่ด้วย “เรื่องเล่า” หรือภาพกราฟิก
- อ่านแล้วเข้าใจทั้งผู้ที่ไม่รู้ IT และผู้ตรวจสอบเชิงลึก
- ทุกหน้าตอบคำถามว่า “ทำอะไร สำคัญอย่างไร พิสูจน์อย่างไร” อย่างน้อยหนึ่งข้อ
- ภาพหน้าจอจริงและภาพประกอบแนวคิดต้องแยกประเภทชัด
