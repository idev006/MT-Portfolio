# MT-Portfolio — SSOT

## 1. Purpose

เอกสารนี้เป็นแหล่งอ้างอิงกลางสำหรับการตัดสินใจด้านเป้าหมาย โครงสร้าง เนื้อหา Personal Brand หลักฐาน และแนวทางการเขียน Portfolio ประจำปี พ.ศ. ๒๕๖๙

เป้าหมายหลักคือจัดทำเอกสารประกอบการประเมินที่ทำให้กรรมการเห็นทั้ง “ผลงานที่พิสูจน์ได้” และ “ศักยภาพของผู้จัดทำ” อย่างรวดเร็ว ชัดเจน และตรวจสอบย้อนกลับได้ โดยไม่สร้างข้อเท็จจริง ตัวเลข หรือบทบาทเกินกว่าหลักฐานที่มี

## 2. Target Audience & Communication Strategy

กลุ่มผู้อ่านหลักคือผู้บังคับบัญชาระดับสูง/คณะกรรมการพิจารณา ซึ่งมีเวลาพิจารณาจำกัด และโดยทั่วไปไม่ได้มีพื้นฐานเชิงเทคนิคด้าน IT, AI, Data, Web Application, Automation หรือ Computer Vision ในระดับลึก

ดังนั้นทุกชิ้นงานต้องสื่อสารด้วย “ภาษาของผู้บริหาร” มากกว่า “ภาษาของโปรแกรมเมอร์” โดยใช้หลักดังนี้:
- ผลต่อภารกิจมาก่อนชื่อเทคโนโลยี
- เริ่มจากปัญหา/ความต้องการ → สิ่งที่ทำ → ผลที่เกิดขึ้น → ประโยชน์ต่อราชการ
- ใช้คำที่เข้าใจง่าย เช่น ลดเวลา ลดขั้นตอน ทำให้ข้อมูลพร้อมใช้ ช่วยวางแผน ช่วยติดตาม ช่วยตัดสินใจ
- หากจำเป็นต้องใช้ศัพท์เทคนิค ให้มีคำอธิบายไทยสั้น ๆ กำกับ
- One Page Report ต้องทำให้กรรมการเข้าใจสารหลักภายในประมาณ 30–60 วินาที และเกิดแรงจูงใจให้เปิดอ่านสรุป 3 หน้าและเล่มใหญ่ต่อ

## 3. Brand Positioning

**Brand Core**

> คิดวิเคราะห์ วางระบบ พัฒนาคน ใช้เทคโนโลยีอย่างเหมาะสม เพื่อขับเคลื่อนงานสู่ผลสัมฤทธิ์

**Brand Interpretation**

ผู้รับการประเมินมีจุดเด่นด้านการคิดวิเคราะห์และออกแบบระบบงาน สามารถมองปัญหาจากการปฏิบัติงานจริง ออกแบบหรือปรับปรุงกระบวนงาน ถ่ายทอดและพัฒนาผู้ร่วมงาน และเลือกใช้ข้อมูล ความรู้ และเทคโนโลยีที่เหมาะสมเพื่อเพิ่มประสิทธิภาพของหน่วยงาน

แนวคิดการทำงานหลักคือ **Work Smart** โดยประยุกต์ใช้คน เครื่องมือ วิธีการ ข้อมูล และเทคโนโลยีอย่างเหมาะสม ลดขั้นตอนที่ไม่ก่อให้เกิดคุณค่า และใช้ทรัพยากรอย่างคุ้มค่า

**สิ่งที่ไม่ควรทำ**
- ไม่สร้างภาพว่าเป็น “ผู้บริหารครบทุกด้าน” หากหลักฐานยังไม่รองรับ
- ไม่ทำให้ AI / Python / Dashboard / Computer Vision เป็นตัวแบรนด์
- ไม่ใช้ตัวเลขผลลัพธ์ที่ไม่มีหลักฐาน
- ไม่เรียกระบบต้นแบบว่าใช้งานจริง หากเป็นเพียงงานศึกษา/สาธิต
- ไม่ตีความภาพถ่ายเกินกว่าสิ่งที่ภาพและ metadata รองรับ

## 4. Narrative Standard

ใช้โครงสร้างมาตรฐาน:

**ปัญหา/ความต้องการ → สิ่งที่ดำเนินการ → บทบาทของข้าฯ → ความท้าทาย → ผลลัพธ์/ประโยชน์ → แนวทางประยุกต์/ต่อยอด → หลักฐาน**

ผลลัพธ์มาก่อนเครื่องมือ และประโยชน์ต่อราชการมาก่อนรายละเอียดเชิงเทคนิค

## 5. Evidence / Forensic Documentation Rule

เอกสารทั้งชุดใช้หลัก **Evidence-Based / Forensic Documentation**

- ทุกข้อเท็จจริงต้องมีแหล่งที่มา
- แยกข้อเท็จจริงออกจากข้อเสนอเชิงตีความ
- ตัวเลขต้องมีหลักฐานหรือคำยืนยันโดยตรงจากเจ้าของผลงาน
- ภาพถ่ายต้องมี provenance หรือ metadata เท่าที่มี
- กฎหมาย ระเบียบ คำสั่ง และภารกิจหน้าที่ ต้องตรวจจากต้นฉบับทางการก่อนอ้างเลขมาตรา/ข้อ/คำสั่ง
- ถ้าหลักฐานไม่พอ ให้ระบุว่ายังไม่ควรใช้แทนการเติมข้อมูลเอง
- บทสัมภาษณ์ผู้จัดทำเป็น Primary Source สำหรับวิธีคิด ตัวตน และแนวทางการทำงาน สามารถเรียบเรียงถ้อยคำได้ แต่ต้องคงแกนแนวคิดเดิม

## 6. Prototype Rule

ใช้ถ้อยคำ เช่น
- ศึกษาและพัฒนาระบบต้นแบบ
- ทดลองประยุกต์ใช้
- ใช้สำหรับศึกษาความเป็นไปได้
- สามารถศึกษาต่อยอดได้ตามความเหมาะสม

หลีกเลี่ยง:
- ใช้งานได้จริง
- แม่นยำ
- รองรับการใช้งานจริง
- ระบุตัวบุคคลได้อย่างถูกต้อง
เว้นแต่มีหลักฐานยืนยัน

## 7. Three Deliverables

### A. One Page Report
หน้าที่: **ทำให้กรรมการเห็นภาพรวมตัวตน คุณค่า และผลงานเด่นภายใน 30–60 วินาที และอยากเปิดอ่านเอกสารส่วนถัดไป**

หลักการ:
- ไม่ยัดทุกผลงานลงหน้าเดียว
- เลือกเฉพาะผลงานและศักยภาพที่มีผลต่อการตัดสินใจและมีหลักฐานรองรับชัดเจน
- ภาษาสั้น กระชับ ไม่ใช้ศัพท์เทคนิคเกินจำเป็น
- ใช้ภาพช่วยสื่อสารมากกว่าข้อความยาว
- Header และ Footer ต้องกระชับ เพื่อสงวนพื้นที่ให้ content หลัก
- สัดส่วนแนะนำ: Header 12–15% / Main Content 80% โดยประมาณ / Footer 3–5%
- กรอบรูปผู้รับการประเมินเป็นแนวตั้ง อัตราส่วนสูง:กว้าง = 4:3
- พื้นที่โลโก้ใช้กรอบเส้นประบาง ๆ ไม่มีพื้นหลังสี เพื่อให้ผู้จัดทำใส่โลโก้ภายหลัง

มิติที่ควรเห็น:
1. แนวคิดการทำงาน / Work Smart
2. ผลงานที่พิสูจน์วิธีคิดและสร้างผลลัพธ์
3. สนับสนุนผู้บังคับบัญชาและภารกิจหน่วย
4. การศึกษาและประยุกต์ใช้ AI / งานต้นแบบ
5. การพัฒนาคนและทีมงาน
6. คุณธรรมและการได้รับการยอมรับ
7. การใฝ่รู้และพัฒนาตนเองอย่างต่อเนื่อง

### B. สรุปผลการปฏิบัติงานไม่เกิน ๓ หน้า
หน้าที่: **ทำให้เข้าใจคุณค่า Personal Brand และผลสัมฤทธิ์สำคัญอย่างรวดเร็ว**

หลักการ:
- อ่านได้ภายในไม่กี่นาที
- เห็น Brand และผลงานเด่นตั้งแต่หน้าแรก
- ทุกข้อความต้องมีหลักฐานรองรับในเล่มใหญ่
- ไม่อัดภาพหรือข้อความจนแน่น

### C. เล่มใหญ่ — ผลการปฏิบัติงาน
หน้าที่: **พิสูจน์**

ประกอบด้วยผลงาน ความรู้ความสามารถ ภารกิจ หลักฐาน ภาพหน้าจอ ใบประกาศ หนังสือคำสั่ง และภาคผนวก

## 8. Evidence Strategy

**เนื้อหาหลัก = สรุปคุณค่า**  
**ภาคผนวก = หลักฐานเต็ม**

ใบประกาศส่วนใหญ่ควรอยู่ภาคผนวก โดยในเนื้อหาหลักใช้ตารางสรุปหลักสูตร/สถาบัน/องค์ความรู้/การนำไปใช้

รางวัลหรือประกาศเกียรติคุณที่สะท้อน “ผลงานที่ได้รับการยอมรับ” อาจนำมาแสดงในเนื้อหาหลักได้

## 9. Supporting Dimension — People

แสดงเท่าที่มีหลักฐานจริง เช่น
- ชี้แจงเป้าหมาย วัตถุประสงค์ และกระบวนงานก่อนมอบหมายงาน
- สอนให้เข้าใจและทำงานได้จริง
- ทำงานเป็นทีมและปฏิบัติงานทดแทนกันได้
- กำชับวินัยและการปฏิบัติตามกฎหมาย ระเบียบ คำสั่ง และจรรยาบรรณ
- Brief / Coaching ระหว่างปฏิบัติ

มิตินี้ใช้ช่วยให้ภาพไม่แคบเป็น “คนเก่งเทคนิค” แต่ไม่ขยายเกินข้อเท็จจริง

## 10. Language Rule

- ใช้ “ข้าฯ” เป็นสรรพนามมาตรฐาน
- ภาษาราชการอ่านง่าย กระชับ ไม่โอ้อวด
- สามารถปรับถ้อยคำจากบทสัมภาษณ์ได้ แต่ต้องรักษาแกนความคิดเดิม
- ไม่ใช้ถ้อยคำ “สมควรเลื่อนตำแหน่ง” หรือข้อความขายตรง

## 11. Soft Closing

ประโยคแกน:

> ข้าฯ มุ่งพัฒนาความสามารถในการคิดวิเคราะห์ วางระบบ พัฒนาคนและกระบวนงาน ตลอดจนเลือกใช้ข้อมูล ความรู้ และเทคโนโลยีอย่างเหมาะสม เพื่อให้เกิดผลสัมฤทธิ์และประโยชน์ต่อหน่วยงานและทางราชการอย่างต่อเนื่อง


## 12. Mandatory communication lock — owner corrections 2026-10-17 (supersedes inconsistent drafts)

**งานนี้คือ “สรุปผลการปฏิบัติงาน/สรุปผลการปฏิบัติราชการ” ไม่ใช่แค็ตตาล็อกหรือโฆษณาโปรแกรม**. ชื่อโปรแกรมเป็นข้อมูลรอง; คุณค่าต่อองค์กรและผลการปฏิบัติงานเป็นสารหลัก. ทุกผลงานต้องผ่านรูปแบบ **ปัญหา/ความต้องการ → สิ่งที่ข้าฯ ลงมือดำเนินการ → ผลที่เกิดขึ้น (ระบุระดับการยืนยัน) → ประโยชน์ต่อหน่วยงาน/ทางราชการ**. ห้ามใช้เฉพาะชื่อระบบ+คุณสมบัติหรือกล่องกราฟิกแทนการเล่าเรื่อง.

### Confirmed cooperative receipt case (page 1 — work improvement, NOT analytics)
- **ปัญหา:** สหกรณ์มีใบเสร็จสำหรับส่งสมาชิกหลายร้อยใบ แต่ละใบต้องใส่โลโก้ ลายเซ็นผู้จัดการสหกรณ์ และข้อความ หากให้เจ้าหน้าที่ประทับ/จัดการทีละใบจะใช้เวลานานและเป็นงานซ้ำ.
- **สิ่งที่ทำ:** พัฒนาโปรแกรมช่วยใส่โลโก้ ลายเซ็น และข้อความลงบนใบเสร็จจำนวนมากในการประมวลผลครั้งเดียว.
- **ผล:** ใบเสร็จ/เอกสารมากกว่า ๒๐๐ หน้าเสร็จภายในไม่เกิน ๑ นาที — เจ้าของผลงานยืนยัน; ต้องรวบรวมหลักฐานทดสอบเพิ่มเติม.
- **ประโยชน์:** ลดภาระงานประทับเอกสารทีละใบและลดเวลาจัดเตรียมใบเสร็จให้สมาชิก.
- **ห้าม:** เรียกงานนี้ว่าโปรแกรมวิเคราะห์ข้อมูลหรือการประมวลผลเชิงวิเคราะห์; ห้ามอ้างการประหยัดเป็นตัวเลขอื่นโดยไม่มีหลักฐาน.

### Layout/content rules reaffirmed by owner
- ชื่อหน่วยงานตรงตัว: **ตำรวจภูธรภาค 6**.
- แสดงชื่อ-ตำแหน่งผู้รับการประเมิน: **ร้อยตำรวจเอก จิรัฎฐ์ธรณ์ จิตศิริ** / **รอง สว.ฝอ.๖ บก.อก.ภ.๖**.
- ต้องมี main topic และหัวข้อรอง; header/footer ขนาดเล็ก; เนื้อหาหลักกินพื้นที่ส่วนใหญ่; คำสั้น เข้าใจเร็ว เหมาะผู้ประเมินอาวุโสเวลาจำกัด.
- **ไม่ใส่โลโก้จริง; หากกำหนดพื้นที่โลโก้ ให้ทำเป็นกรอบเส้นประบาง ๆ ว่างไว้ให้เจ้าของผลงานใส่ภายหลัง**. นี่คือคำสั่งล่าสุดและ supersede นโยบายเดิมที่ห้ามกรอบโลโก้. ห้าม AI สร้างโลโก้ขึ้นเอง.
- ภาพผู้รับการประเมินในหน้า ๑ ให้เว้นกรอบแนวตั้ง สูง:กว้าง 4:3 ไม่ใส่ภาพบุคคลสมมติ.
- ๕ กลุ่มผลการปฏิบัติงานและลำดับการสื่อสาร ๓ หน้าเป็นโครงหลัก; การสลับผลงานสำคัญต้องมีเหตุผลเชิงหลักฐานและความเห็นชอบผู้ใช้.

### Hard stop gate before every image
Do not generate or submit artwork unless (1) each featured case has a checked problem/action/outcome/benefit story with no unverified invention; (2) all locked identity, headings and organization text are present; (3) blank dashed logo frame if a logo slot is included, no rendered unit logo; (4) compact header/footer, high content priority and readable type; (5) actual-vs-concept/prototype labels preserved. If any gate fails, revise copy and wireframe first. Document the comparison against Content Lock and latest owner correction in the handoff. No Design-as-Code layout renderer.
